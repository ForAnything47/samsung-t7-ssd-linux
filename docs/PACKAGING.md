# Local Arch package

This repository can generate a local Arch/CachyOS package. It is a development
candidate, not a published release or AUR package. Build it as a normal user;
use administrator privileges only for installation and device operations.

The package provides the `t7` CLI and optional `t7-gui` interface. For the
device features and hardware limits, see [README](../README.md) and the
[validation record](VALIDATION.md).

## Before building

You need `makepkg` and the package's required dependencies: Python,
`sg3_utils`, `util-linux` and `udisks2`. Plain `makepkg` checks these
dependencies and stops if any are missing; install missing packages with
pacman before rebuilding.

For the GUI, also install `pyside6`, `polkit` and a running desktop
authentication agent. These are optional package dependencies, so installing
this package does not necessarily install them. If PySide6 is unavailable
during `makepkg`, its optional GUI tests are skipped; the CLI tests still run.

## Build and install

From the repository root:

```bash
python3 scripts/prepare_arch.py --out /tmp/t7-arch-build
cd /tmp/t7-arch-build
makepkg --verifysource
makepkg
```

Preparation checks `SHA256.json`; `makepkg` verifies the source archive and
runs offline tests.

Inspect the generated package filename and file list before installing it:

```bash
ls -1 *.pkg.tar.zst
pacman -Qlp ./samsung-t7-ssd-linux-0.1.0.dev1-13-any.pkg.tar.zst
sudo pacman -U ./samsung-t7-ssd-linux-0.1.0.dev1-13-any.pkg.tar.zst
```

Use the **exact filename generated by your build**. Before replacing a manual
installation, inspect its files and preserve its runtime records.

## Check the installation

```bash
pacman -Qkk samsung-t7-ssd-linux
t7 --help
t7 list
t7-gui
```

`t7 list` reads host information only. Start `t7-gui` as a normal desktop user;
device operations request administrator authorization separately.

A status query sends a Discovery command to the SSD. After selecting the
correct serial and unmounting its partitions, you can run
`sudo t7 status --serial YOUR_SERIAL --execute`. See [CLI usage](CLI-USAGE.md)
and [GUI usage](GUI-USAGE.md) before changing password settings.

## Installed files and runtime records

| Path | Purpose |
| --- | --- |
| `/opt/samsung-t7-ssd-linux/` | Root-owned application code. |
| `/usr/bin/t7` | CLI launcher; device operations need explicit `--execute`. |
| `/usr/bin/t7-gui` | GUI launcher; refuses root execution. |
| `/usr/share/applications/t7.desktop` | Unofficial T7 SSD Password Manager desktop entry. |
| `/usr/share/doc/samsung-t7-ssd-linux/` | Installed user and developer documentation. |
| `/var/opt/samsung-t7-ssd-linux/` | Root-owned runtime records, created on first use; not packaged. |

Per-run logs are stored in
`/var/opt/samsung-t7-ssd-linux/state/<device-key>/logs/`.
Optional detailed results use `runs/` and `compatibility-runs/` under the
same runtime root. Runtime directories use mode `0700`; log files use
`0600`. The GUI reads selected-device logs through its authorized worker.

Source-tree runs keep separate application-relative `state/`, `runs/` and
`compatibility-runs/` directories. Installation does **not** migrate them
or older `/opt` records. Existing `pending.json` files are not used to
block operations and are neither moved nor deleted automatically. Review
and preserve them yourself if needed.

All installed users share the root-owned runtime tree. Ordinary users cannot
read its files directly, and the GUI log viewer restricts reads to the selected
device. These logs are not a complete audit trail: failures before the device
flow can appear only in CLI/GUI output. See [operation logs](OPERATION-LOGS.md).

## Upgrade or remove

Finish device work and close the GUI before changing the package. To upgrade,
build a new candidate and use `sudo pacman -U` with its **exact package file**.
To remove the installed package:

```bash
sudo pacman -R samsung-t7-ssd-linux
```

There are no install or removal hooks that migrate or delete runtime records.
Removing the package leaves `/var/opt/samsung-t7-ssd-linux/` for deliberate
review; remove it separately only after deciding that its logs are no longer
needed. Upgrade, removal and multi-user behavior have **not** yet been
exercised as release tests.
